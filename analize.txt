 4) NOVO RECURSO C - CONFIRMAÇÃO DE PRESENÇA NO EVENTO
====================================================================
OBJETIVO:
  O usuário pode tocar em um botão "Confirmar presença" na mensagem,
  e o admin visualiza a estatística de confirmações por mensagem.

VIABILIDADE: MÉDIA-ALTA (rank 4/5) - ESFORÇO: MÉDIO

JUSTIFICATIVA TÉCNICA:
  - Segue o MESMO padrão já implementado nas estatísticas de acesso
    (tabela "acessos" + RLS + função RPC stats_acessos).
  - Reutiliza o disciplina dispositivo_id do AccessLog (já existente).

MUDANÇAS NECESSÁRIAS NO BANCO (Supabase):
  1) Ampliar tabela "mensagens" (opcional, para o evento):
     ALTER TABLE public.mensagens
       ADD COLUMN IF NOT EXISTS evento_titulo TEXT,
       ADD COLUMN IF NOT EXISTS evento_data   TIMESTAMPTZ,
       ADD COLUMN IF NOT EXISTS evento_local  TEXT;

  2) Nova tabela "confirmacoes_presenca":
     CREATE TABLE IF NOT EXISTS public.confirmacoes_presenca (
       id             BIGSERIAL PRIMARY KEY,
       mensagem_id    BIGINT REFERENCES public.mensagens(id)
                      ON DELETE CASCADE,
       dispositivo_id TEXT NOT NULL,
       nome           TEXT,
       criado_em      TIMESTAMPTZ NOT NULL DEFAULT now(),
       UNIQUE(mensagem_id, dispositivo_id)  -- impede confirmação dupla
     );

  3) RLS na nova tabela:
     ALTER TABLE public.confirmacoes_presenca ENABLE ROW LEVEL SECURITY;

     -- Qualquer pessoa pode confirmar presença (INSERT público)
     CREATE POLICY presenca_insert_public
       ON public.confirmacoes_presenca
       FOR INSERT TO anon, authenticated
       WITH CHECK (true);

     -- Apenas admin (autenticado) pode ler as confirmações
     CREATE POLICY presenca_select_auth
       ON public.confirmacoes_presenca
       FOR SELECT TO authenticated
       USING (true);

     GRANT INSERT ON public.confirmacoes_presenca TO anon;
     GRANT INSERT, SELECT ON public.confirmacoes_presenca TO authenticated;

  4) Função para contar confirmações por mensagem:
     CREATE OR REPLACE FUNCTION public.stats_confirmacoes(m_id bigint)
     RETURNS bigint
     LANGUAGE sql
     SECURITY DEFINER
     SET search_path = public
     AS $$
       SELECT COUNT(*) FROM public.confirmacoes_presenca
       WHERE mensagem_id = m_id;
     $$;
     GRANT EXECUTE ON FUNCTION stats_confirmacoes(bigint) TO authenticated;

MUDANÇAS NECESSÁRIAS NO CÓDIGO (Flutter):
  - No carrossel/mensagem: botão "✅ Confirmar presença".
  - Ao tocar: INSERT em confirmacoes_presenca com dispositivo_id.
  - Tratar erro de UNIQUE (usuario ja confirmou -> avisar "Já confirmado").
  - No admin: nova seção/aba "Presença" listando cada mensagem
    + numero de confirmacoes (chamando stats_confirmacoes).

====================================================================
 7) PONTOS DE ATENÇÃO
====================================================================
1. RLS ATUAL da tabela mensagens:
     SELECT ... USING (ativa = true)
   -> Só retorna mensagens ATIVAS para anon.
   -> O admin (authenticated) usa outra policy e consegue ver todas.

2. AUTOPLAY & UX:
   -> A rolagem automática deve PAUSAR quando o usuário arrasta,
      para não "roubar" o controle (boa prática).

3. DISPOSITIVO_ID:
   -> Reutilizar o mesmo disciplina_id do AccessLog para garantir
      consistência nas confirmações de presença.

4. PERFORMANCE:
   -> A tabela de mensagens é pequena; buscar todas as ativas
      é leve, sem risco de gargalo.

5. DUPLA CONFIRMAÇÃO:
   -> A constraint UNIQUE(mensagem_id, dispositivo_id) impede que
      o mesmo dispositivo confirme 2x na mesma mensagem.
